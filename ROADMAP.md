# Zero OS Roadmap

## Strategic Focus
The immediate priority is the Pure Logic Authority Kernel. New UI, antivirus and agent features remain secondary until consequential execution is governed by one constitutional authority model.

## Authority Kernel Milestone
Required architecture:
1. Reality Ledger with provenance, assumptions, dependencies, scope and contradiction state.
2. Discovery/Scope separation: winner selection cannot certify representational completeness.
3. Plurality preservation for viable alternatives.
4. Identity/Trust Authority with consequence-sensitive evidence requirements.
5. Capability and Authority Ledgers with expiry, revocation and dependency propagation.
6. Objective Authority Ledger.
7. Legal-State Invariant Engine with executable/formal checks for critical properties.
8. Protected Correction Plane separating runtime tamper resistance from architecture revisability.
9. Resource Law verification budgets.
10. Active independent evidence generation for contested authority.
11. Reversible executor and blast-bound actions.
12. Independent Outcome Verifier.
13. Recursive Architecture Promotion Authority.

Exit criteria:
- No discovery confidence, consensus score, memory weight or self-reported verifier confidence can grant action authority.
- All identified consequential execution paths require exact scoped authority at the final sink.
- Privileged actions require identity provenance and consequence-appropriate authentication evidence.
- Critical objectives and architecture revisions carry independent authority contracts.
- Expiry and revocation are enforced, not decorative metadata.
- A failed critical invariant blocks promotion rather than lowering an average score.
- Correction infrastructure cannot be rewritten or self-certified by the subsystem being corrected.
- Contested scope requests new discriminating evidence instead of relaxing standards.
- High/critical consequence actions require independent outcome verification.

## Parallel Track A: AI/Runtime Platform
Target:
- Stable smart OS layer across Windows, Linux and macOS through Hyperlayer while authority-kernel migration proceeds.

Deliverables:
1. Hyperlayer adapters parity for file/process/network actions.
2. Harden Zero-AI loop: novelty -> adaptation -> model evolution -> traceability.
3. Native adaptive cyber defense: identity, trust, scoped capability, quarantine, rollback and evidence preservation.
4. Unified observability for authority, contradiction, capability and correction state.
5. Package/runtime policy for open source contributors.

Exit criteria:
- Cross-platform command parity for core actions.
- Reliability and security tests pass in CI.
- No identified privileged bypass around the Pure Logic authority kernel.

## Parallel Track B: From-Scratch Kernel R&D
Target:
- Build a real kernel foundation while preserving explicit legal-state invariants.

Deliverables:
1. Syscall specification and capability contract.
2. Scheduler prototype and test harness.
3. Memory manager design and page model.
4. Driver contracts for disk/network/display/input.
5. Boot path and independently protected safe-mode recovery.
6. Formal/executable models for critical illegal-state properties.

Exit criteria:
- Kernel design docs and prototypes are versioned and test-backed.
- Critical invariants have explicit models/checkers.
- Clear migration path exists from host-bridged Hyperlayer to native kernel modules.

## Pre-production Attack-Surface Reduction
Every permission, interface, dependency and privileged process family must justify necessity before production.

Unnecessary capability -> remove.

Necessary capability -> bind to explicit scope, provenance, blast bound, expiry/revocation and outcome verification requirements.

Capability that is unnecessary but cannot be safely removed -> block promotion until resolved.

## v1.0 Stable Open System Release
Target:
- Public open source release with documented governance and version-stable interfaces.

Deliverables:
1. Version-stable core architecture contracts, not epistemically frozen truth.
2. Signed release process and rollback guides.
3. Protected Correction Plane procedure for architecture-level defects.
4. Long-run daemon reliability validation.
5. Public issue templates for bugs and security.
6. Reference deployment guide for local and lab setups.

Exit criteria:
- Release checklist complete.
- Docs match implementation.
- Layered defenses survive the declared attack simulation set within demonstrated scope.
- Authority-kernel promotion audit reports no identified critical bypass.
- Runtime/dynamic/native/dependency/hardware limitations remain explicitly documented rather than converted into a global security claim.
